## Answers

**1. Blocking vs cosmetic gaps**

Blocking (client actively uses it, new server has no direct target, dictation would break):
- Desktop `stt run --port` launch contract gone; new binary has no `run`/`--port` args (D).
- Provider start/stop/status/descriptor lifecycle entirely removed — desktop's `ensure_runtime_started`/`spawn_backend`/`stop_backend_process` and the SDK's descriptor-driven auth have nothing to call (B, D, E).
- `getHardware()` / `getSystemMemory()` have no endpoint (B).
- Token/port discovery: desktop currently supplies the token and a fixed port; new server generates both itself with no discovered handoff path evident in code read so far (D, F).
- SDK's `model` field omission — new server requires `model` (400s a request the SDK sends today for any provider without an explicit model override) (E).
- SDK sends `prompt` without checking capability; new server 422s instead of ignoring for non-Whisper models (E).

Cosmetic / non-blocking:
- Path renames (`/v1/health`→`/health`, `/v1/readiness`→`/readiness`).
- Response field renames/reshapes on `/v1/models`, operations polling shape.
- Loss of device-specific reasoning text in recommendations (still gets a model list).

**2. Smallest fix + ownership per GOAL.md boundary**

- Model/prompt required-field breakages → **client (Whisper Vibes/SDK) owns**: always send `model:"default"` when unset; read `/v1/local/models/selected` capability matrix before sending `prompt`/`language`/`temperature`. This matches GOAL.md's "Voice Typer owns... vocabulary, prior-chunk prompt construction" and "the SDK adapter reads the selected model's effective matrix and omits unsupported/unknown optional fields."
- Health/path renames → **client owns** (trivial string change in `stt-server-client.ts`/`api.ts`).
- Provider lifecycle/descriptor/hardware/port/token discovery → **shared, but server must define the missing contract first**: GOAL.md commits the server to "stable loopback address," "generate a bearer token... protect it with restrictive Windows ACLs," and Windows Service auto-start, but doesn't yet specify a documented client-facing discovery mechanism (well-known port constant + token file path client can read, or a small unauthenticated `/v1/local/config`-lite bootstrap). Smallest fix: server publishes a fixed documented port and a token file path (or registry value) desktop can read directly — server-side spec work, then a client-side read-instead-of-supply change. This is explicitly cross-boundary and is the single largest remaining open item — not resolved in the GOAL.md decision log entries read.

**3. Health-card answer** — see section G above: interim card can show ready/not-ready, active model id, and observed CPU/Vulkan backend from `GET /readiness`; it cannot show GPU/VRAM presence or live memory the way today's card does, since those endpoints don't exist in the new server.

**4. CLI verdict** — grep of `scripts/`, `.github/`, and `apps/` (both desktop and web) found no script or CI invocation of `stt hardware|recommend|descriptor|reset|verify|bench|provider|model` as literal CLI subcommands; the only two script hits (`scripts/setup-voice-typer-dev-signing.ps1`, `scripts/sign-and-launch-voice-typer.ps1`) did not contain actual `stt <subcommand>` invocations on closer grep. Desktop invokes only `stt run --port <n>` as a sidecar. **Verdict: the new binary does not need to replicate `status`/`models list/pull`/`bench` as CLI subcommands for anything currently automated** — all real usage is through desktop's single `run` sidecar launch plus the HTTP API. `bench` has no scripted caller either, though GOAL.md's own success criteria ("Real Voice Typer dictation is benchmarked...") implies *some* bench tooling is needed for the project's own validation, just not necessarily as a shipped `stt bench` subcommand.

**5. SDK breakages against the new API** (verified/inferred, see E):
- SDK omits `model` field when unset → new server requires it (**verified requirement in GOAL.md text**; server-side enforcement point at `api.rs:825` `model_not_active`, exact validation-order not fully traced — **inferred** that omission itself, not just wrong value, will fail, based on GOAL.md "file and model are required").
- SDK always sends `prompt` for any provider → new server hard-errors non-Whisper models with `unsupported_capability` (**verified live in `docs/parity-ledger.md`** Parakeet test).
- Port/token/URL are descriptor-driven in the SDK (`local-runtime.ts` constructor takes `baseUrl`/`auth` from a descriptor) → no descriptor exists on the new server; SDK's construction contract itself needs a new source of `baseUrl`/token (**verified as removed via GOAL.md decision**, client-side fix not yet designed).
- `listModels()` hits `/v1/config`, which doesn't exist on the new server (**verified by absence** — grep of `api.rs` found no `/v1/config` route, only `/v1/local/config`).
- Language-hint fallback silently diverges (no `language_hint_applied:false`) — **verified live bug** in `docs/parity-ledger.md` Bug 2, could surface as silently-wrong-language in the app if the SDK doesn't check `x_diagnostics.language_evidence`.
